monkey_dust

A native Linux engine that renders the world of Kenshi from your own installed copy of the game, built to run at 60 FPS on weak integrated GPUs (target: Intel HD 520, full 1920×1080).

Нативний рушій для Linux, що рендерить світ Kenshi з вашої власної встановленої копії гри і розрахований на 60 FPS на слабких вбудованих GPU (ціль: Intel HD 520, повні 1920×1080).

●Kenshi install requiredПотрібна інсталяція Kenshi
●Intel HD 520 · 1920×1080 · 60 FPS (goal)(мета)
●Engine: MIT · Tools: GPL-3.0 · Game: proprietaryвласницька

What this is

  • A rendering engine for Kenshi's world on Linux: native, no Wine/Proton at runtime, SDL3 + SDL_GPU over Vulkan.
  • It reads Kenshi's data at startup (the OpenMW model). Content is edited with Kenshi's own editor, the Forgotten Construction Set (FCS).
  • Its niche is weak hardware. Other Kenshi re-implementations target discrete GPUs; this one targets a 2016 laptop iGPU.

What this is not (yet)

  • Not a playable game. No NPCs, combat, trade or UI from Kenshi yet.
  • Not a Kenshi remake. Kenshi is © Lo-Fi Games; this is an independent, unofficial project.
  • Nothing to download yet. The engine library is public; the game executable is in a private repository.

Що це

  • Рушій, що рендерить світ Kenshi під Linux: нативно, без Wine/Proton під час роботи, SDL3 + SDL_GPU поверх Vulkan.
  • Під час запуску читає дані Kenshi (модель OpenMW). Контент редагується власним редактором Kenshi, Forgotten Construction Set (FCS).
  • Ніша — слабке залізо. Інші переписування Kenshi розраховані на дискретні GPU; цей — на вбудовану графіку ноутбука 2016 року.

Чим це (поки) не є

  • Це не гра, в яку можна грати. NPC, бою, торгівлі й інтерфейсу з Kenshi ще немає.
  • Це не ремейк Kenshi. Kenshi © Lo-Fi Games; це незалежний неофіційний проєкт.
  • Завантажити поки нічого. Бібліотека рушія публічна; виконуваний файл гри — у приватному репозиторії.
You need Kenshi

The engine contains no Kenshi data and never will. It reads the game's files (FCS .base/.mod, heightmap, maps; later meshes and textures) from your own legal copy (Steam or GOG). Nothing is copied into the repositories, and the engine never writes to the Kenshi folder.

Потрібна Kenshi

Рушій не містить даних Kenshi і не міститиме. Він читає файли гри (FCS .base/.mod, карту висот, карти; згодом моделі й текстури) з вашої власної легальної копії (Steam або GOG). Нічого не копіюється в репозиторії, і рушій нічого не пише в теку Kenshi.

How KENSHI_DIR is used

md::KenshiDir() returns $KENSHI_DIR (an empty value disables the install on purpose). md::KenshiLandFile(name, fallback) returns <KENSHI_DIR>/data/newland/land/<name> when it exists, else the fallback, and logs the choice once. Tests that need real data run only when KENSHI_DIR is set.

Як використовується KENSHI_DIR

md::KenshiDir() повертає $KENSHI_DIR (порожнє значення навмисно вимикає інсталяцію). md::KenshiLandFile(name, fallback) повертає <KENSHI_DIR>/data/newland/land/<name>, якщо файл є, інакше запасний шлях, і пише вибір у лог один раз. Тести зі справжніми даними запускаються лише з KENSHI_DIR.

ModsМоди

Mods are read the way Kenshi reads them: data/mods.cfg order, then the mods/ and Steam Workshop folders; records are merged in load order (io/fcs_gamedata.h). Edit content in Kenshi's FCS. Workshop mods are not yet verified on real data.

Моди читаються так, як їх читає Kenshi: порядок з data/mods.cfg, далі теки mods/ і Steam Workshop; записи зливаються в порядку завантаження (io/fcs_gamedata.h). Контент редагується у FCS. Моди Workshop на справжніх даних ще не перевірені.

TerrainЛандшафт

  • Heights: TerrainAtlas reads fullmap.tif (16385², uint16) at startup and keeps every 2nd sample: 8256² = 64×64 zones × 129² vertices, 3.6 m. Fallback: the offline world_hmap.r16. Kenshi's own grid is 1.8 m (Plugin_Terrain_x64.dll, getHeight 0x180014430).
  • Queries: TerrainQuery is the single source of heights, normals and slopes for gameplay.
  • Normals: Kenshi's 6-neighbour fan (decoded from the plugin's patch builder 0x1800047a0), default MD_NORMAL_BAKE=3.
  • Geometry: TerrainQuadtree, fixed depth (kFlatLodDepth = 3); no geomorph, no skirts, so no T-junction seams by construction. Kenshi's own LOD uses a screen-space error metric with threshold 8; parity there is not a goal for now.
  • Shading: G-buffer pass, then a screen-space resolve: base / grass / slope / cliff / dirt / road layers per biome, per-layer mip selection (fixes zone seams), cliff normal flips as in Kenshi's shader, ambientmap on. Biome weights currently come from a tent blend between zone centres; Kenshi's per-pixel blendMap blend is milestone M2.2.
  • Scatter: FeatureScatterSystem places objects from Kenshi's features.dat; there is no procedural terrain or clutter generation.
  • Висоти: TerrainAtlas читає fullmap.tif (16385², uint16) під час запуску і бере кожен 2-й відлік: 8256² = 64×64 зони × 129² вершин, 3,6 м. Запасний варіант — офлайн world_hmap.r16. Власна сітка Kenshi — 1,8 м (Plugin_Terrain_x64.dll, getHeight 0x180014430).
  • Запити: TerrainQuery — єдине джерело висот, нормалей і схилів для ігрової логіки.
  • Нормалі: віяло з 6 сусідів, як у Kenshi (розібрано з будівника патчів плагіна 0x1800047a0), за замовчуванням MD_NORMAL_BAKE=3.
  • Геометрія: TerrainQuadtree фіксованої глибини (kFlatLodDepth = 3); без геоморфу й юбок, тож T-швів немає за побудовою. LOD у Kenshi — за екранною похибкою з порогом 8; паритет тут поки не мета.
  • Шейдинг: прохід G-буфера, потім екранне розв'язання: шари base / grass / slope / cliff / dirt / road для кожного біому, мип для кожного шару окремо (прибирає шви зон), перевертання нормалей кручі як у шейдері Kenshi, ambientmap увімкнено. Ваги біомів зараз — «намет» між центрами зон; змішування за blendMap для кожного пікселя, як у Kenshi, — етап M2.2.
  • Об'єкти: FeatureScatterSystem розставляє об'єкти з features.dat Kenshi; процедурної генерації рельєфу чи дрібних об'єктів немає.

Performance measurementЗаміри продуктивності

  • Only on terrain-dominated frames: scenarios place the camera with set_camera_pose_world and check md.terrain_pixel_fraction() ≥ 80 %.
  • RenderPassGraph switches any registered pass on or off at runtime (md.set_render_pass_enabled); with md.get_gpu_ms() this splits frame cost pass by pass without rebuilding.
  • A/B comparisons run in one process, several interleaved blocks (ABBA), to cancel GPU clock drift.
  • Baseline (1080p, HD 520): south_hive 51.1 ms, worst_24_12 52.1 ms, owner_point 65.6 ms; with the terrain resolve off ≈ 29 ms.
  • Лише на кадрах, де переважає земля: сценарії ставлять камеру через set_camera_pose_world і перевіряють md.terrain_pixel_fraction() ≥ 80 %.
  • RenderPassGraph вмикає й вимикає будь-який зареєстрований прохід під час роботи (md.set_render_pass_enabled); разом з md.get_gpu_ms() це розкладає ціну кадру по проходах без перезбірки.
  • Порівняння A/B — в одному процесі, кількома чергованими блоками (ABBA), щоб прибрати дрейф частот GPU.
  • База (1080p, HD 520): south_hive 51,1 мс, worst_24_12 52,1 мс, owner_point 65,6 мс; з вимкненим розв'язанням ландшафту ≈ 29 мс.

ECS

gaia-ecs 1.0.0 (archetype-based, vendored) is the only backend, behind the MdRegistry/MdEntity facade; no call site touches gaia directly. Relations are used for alliances and NPC relationships. Components are POD and live in components/. Mutation follows collect → apply. Two core bugs found during the migration were fixed upstream (gaia-ecs #42, #43); a third (#39, concurrent .each()) is avoided because JobGraph dispatch is sequential.

gaia-ecs 1.0.0 (на архетипах, вбудований) — єдиний бекенд, за фасадом MdRegistry/MdEntity; жоден виклик не звертається до gaia напряму. Зв'язки (relations) — для союзів і стосунків NPC. Компоненти POD, у components/. Зміни — за схемою зібрати → застосувати. Дві помилки ядра, знайдені під час міграції, виправлено в оригіналі (gaia-ecs #42, #43); третю (#39, паралельний .each()) обходимо, бо JobGraph виконує задачі послідовно.

Physics, navigation, animationФізика, навігація, анімація

  • Jolt Physics — JoltWorld, CharacterVirtual (up to 512 bodies), ragdoll.
  • Recast/Detour — navmesh, async SPSC path worker, PathCache, DetourCrowd (ORCA).
  • ozz-animation — blend/sample/additive; GPU skinning via SSBO (up to 64 bones); analytic 2-bone foot IK on TerrainQuery.
  • For Kenshi characters (later): Ogre .mesh/.skeleton readers, heights under feet from the 1.8 m grid like Terrain::getHeight.
  • Jolt Physics — JoltWorld, CharacterVirtual (до 512 тіл), ragdoll.
  • Recast/Detour — навмеш, асинхронний SPSC-потік шляхів, PathCache, DetourCrowd (ORCA).
  • ozz-animation — змішування, вибірка, адитив; скінінг на GPU через SSBO (до 64 кісток); аналітичний IK стоп на TerrainQuery.
  • Для персонажів Kenshi (пізніше): читачі Ogre .mesh/.skeleton, висота під ногами з сітки 1,8 м, як Terrain::getHeight.

AI

A stackless behaviour-tree VM (30+ node types, zero heap allocation, flat 32 KB node pool), JSON tree loader, sense system (vision cone, sound falloff), director with menace gauge, utility scorer, NPC memory. This predates the Kenshi direction; Kenshi's own AI will be re-implemented from specifications later, not copied.

VM дерев поведінки без стеку (30+ типів вузлів, без виділень пам'яті, плоский пул вузлів 32 КБ), завантажувач дерев з JSON, сенси (конус зору, затухання звуку), режисер зі шкалою загрози, оцінка корисності, пам'ять NPC. Це з часів до напряму Kenshi; AI Kenshi пізніше буде відтворено за специфікаціями, а не скопійовано.

Gameplay systemsІгрові системи

Damage, hit zones and limb severance (combat/); building grid and production chains (building/); versioned binary saves with CRC32 and an upgrade chain (save/, format v11 in the game); Lua 5.4 sandbox with an 8 MB allocator, event bus, flow graph, event scheduler (scripting/); miniaudio (audio/); factions and a 1 Hz world simulation (world/). These are generic and will be wired to Kenshi's FCS data step by step after the world goal.

Шкода, зони влучання й відсікання кінцівок (combat/); сітка будівництва й ланцюги виробництва (building/); бінарні збереження з версіями, CRC32 і ланцюгом оновлень (save/, формат v11 у грі); пісочниця Lua 5.4 з алокатором 8 МБ, шина подій, flow graph, планувальник подій (scripting/); miniaudio (audio/); фракції й симуляція світу 1 Гц (world/). Це загальні системи; до даних FCS Kenshi їх буде під'єднано поступово, після мети зі світом.

Editor & toolsРедактор та інструменти

The tools repository (GPL-3.0) holds the standalone monkey_dust_editor (Dear ImGui), shader hot-reload, the live game command driver used for measurements (qa/game_cmd_driver.py), and Python converters and bakers. Kenshi content itself is edited in Kenshi's FCS, not here.

Репозиторій інструментів (GPL-3.0) містить окремий monkey_dust_editor (Dear ImGui), гаряче перезавантаження шейдерів, драйвер команд живої гри для замірів (qa/game_cmd_driver.py), конвертери й випікачі на Python. Сам контент Kenshi редагується у FCS, не тут.

Flare tiles (legacy)Тайли Flare (спадок)

Until October 2026 the project was an isometric RPG inspired by the Flare engine. That code remains in flare/ (tile map 3D/2D renderers, sprite animation, INI loaders) and md_flare_demo in tools. It is kept working but is not part of the Kenshi world path and is not developed further.

До жовтня 2026 проєкт був ізометричною RPG за мотивами рушія Flare. Цей код лишився в flare/ (рендер тайлів 3D/2D, анімація спрайтів, INI-завантажувачі) і md_flare_demo в інструментах. Він працює, але в шлях світу Kenshi не входить і далі не розвивається.

RulesПравила

Kenshi data and third-party code

  • No Kenshi files in public repositories or releases.
  • Project Okran (MIT) code may be ported to C++ by behaviour, with a file header and a line in THIRD_PARTY.md. Okran is a map, not the truth: every ported module is checked numerically on real Kenshi data.
  • Kenshi shader text is never copied; only formulas are re-implemented.
  • Every claim about Kenshi is backed by its code or data (address, file and line, or a number), not by screenshots.

Code

  • C++17 only. AI is behaviour trees, not FSM/switch states.
  • No heap allocation and no std::vector/std::map growth on hot paths; fixed arrays.
  • No assert(): MD_LOG_WARNING(...) and return. No registry mutation inside iteration: collect → apply.
  • The engine never includes from game/ or tools/. ImGui only under MONKEY_DUST_EDITOR.

Дані Kenshi і сторонній код

  • Жодних файлів Kenshi в публічних репозиторіях і релізах.
  • Код Project Okran (MIT) можна переносити на C++ за поведінкою, із заголовком у файлі й рядком у THIRD_PARTY.md. Okran — карта, а не правда: кожен перенесений модуль перевіряється числом на справжніх даних Kenshi.
  • Текст шейдерів Kenshi не копіюється; відтворюються лише формули.
  • Кожне твердження про Kenshi підтверджується її кодом або даними (адреса, файл і рядок, число), а не скриншотами.

Код

  • Лише C++17. AI — дерева поведінки, не FSM/switch.
  • На гарячих шляхах — без виділень пам'яті й росту std::vector/std::map; фіксовані масиви.
  • Без assert(): MD_LOG_WARNING(...) і return. Без змін реєстру під час обходу: зібрати → застосувати.
  • Рушій не включає файли з game/ чи tools/. ImGui — лише під MONKEY_DUST_EDITOR.
