monkey_dust

A native Linux engine that renders the world of Kenshi from your own installed copy of the game, aimed at weak integrated GPUs (test platform: Intel HD 520).

Нативний рушій для Linux, що рендерить світ Kenshi з вашої власної встановленої копії гри і орієнтований на слабкі вбудовані GPU (тестова платформа: Intel HD 520).

●Kenshi install requiredПотрібна інсталяція Kenshi
●Test platform:Тестова платформа: Intel HD 520
●Engine: MIT · Tools: GPL-3.0 · Game: proprietaryвласницька

What this is

  • A rendering engine for Kenshi's world on Linux: native, no Wine/Proton at runtime, SDL3 + SDL_GPU over Vulkan.
  • It reads Kenshi's data at startup (the OpenMW model). Content is edited with Kenshi's own editor, the Forgotten Construction Set (FCS).
  • Its niche is weak hardware. Other Kenshi re-implementations target discrete GPUs; this one targets a 2016 laptop iGPU.

What this is not (yet)

  • Not a playable game yet. No NPCs, combat, trade or UI from Kenshi. The early prototype game layer was removed on 2026-10-17; new game logic will be written from facts about Kenshi's systems.
  • Not a Kenshi remake. Kenshi is © Lo-Fi Games; this is an independent, unofficial project.
  • Nothing to download yet. The engine library is public; the game executable is in a private repository.

Що це

  • Рушій, що рендерить світ Kenshi під Linux: нативно, без Wine/Proton під час роботи, SDL3 + SDL_GPU поверх Vulkan.
  • Під час запуску читає дані Kenshi (модель OpenMW). Контент редагується власним редактором Kenshi, Forgotten Construction Set (FCS).
  • Ніша — слабке залізо. Інші переписування Kenshi розраховані на дискретні GPU; цей — на вбудовану графіку ноутбука 2016 року.

Чим це (поки) не є

  • Це не гра, в яку можна грати. NPC, бою, торгівлі й інтерфейсу з Kenshi ще немає.
  • Це не ремейк Kenshi. Kenshi © Lo-Fi Games; це незалежний неофіційний проєкт.
  • Завантажити поки нічого. Бібліотека рушія публічна; виконуваний файл гри — у приватному репозиторії.
You need Kenshi

The engine contains no Kenshi data and never will. It reads the game's files (FCS .base/.mod, heightmap, maps; later meshes and textures) from your own legal copy (Steam or GOG). Nothing is copied into the repositories, and the engine never writes to the Kenshi folder.

Потрібна Kenshi

Рушій не містить даних Kenshi і не міститиме. Він читає файли гри (FCS .base/.mod, карту висот, карти; згодом моделі й текстури) з вашої власної легальної копії (Steam або GOG). Нічого не копіюється в репозиторії, і рушій нічого не пише в теку Kenshi.

GoalsМета

By 2026-12-31: the world below plus a minimal playable core — a squad you can select and move, a few NPCs from town data, the simplest melee combat. Partial and rough on purpose; a full Kenshi replacement is a multi-year effort.

До 31.12.2026: світ (нижче) плюс найменше граюче ядро — загін, який можна виділити й вести, кілька NPC з даних міст, найпростіший ближній бій. Свідомо частково й сиро; повна заміна Kenshi — робота на кілька років.

By ~2026-11-08: Kenshi's world on Linux at a stable 60 FPS on an HD 520, 1920×1080: terrain, sky, water, towns and foliage from the Kenshi folder, looking like Kenshi. "Stable" = frame-interval p99 ≤ 16.7 ms on a fixed flight route (town, canyon, desert, horizon; loading hitches count) and a mean ≤ 16.7 ms at three fixed points and near the Hub. Then, by ~2026-11-20: a minimal playable core (a character with Kenshi's mesh and animations, click-to-move on Kenshi's navigation mesh, a squad, a few NPCs, the simplest melee combat); by 31.12 (preliminary): game shell, new game with the character editor, combat and medicine, NPCs and factions, inventory and trade, saves.

Далі, до ~20.11.2026: найменше граюче ядро (персонаж із мешем і анімаціями Kenshi, рух кліком по навігаційній сітці Kenshi, загін, кілька NPC, найпростіший ближній бій); до 31.12 (попередньо): оболонка гри, нова гра з редактором персонажа, бій і медицина, NPC і фракції, інвентар і торгівля, збереження.

How KENSHI_DIR is used

md::KenshiDir() returns $KENSHI_DIR (an empty value disables the install on purpose). md::KenshiLandFile(name, fallback) returns <KENSHI_DIR>/data/newland/land/<name> when it exists, else the fallback, and logs the choice once. Tests that need real data run only when KENSHI_DIR is set.

Як використовується KENSHI_DIR

md::KenshiDir() повертає $KENSHI_DIR (порожнє значення навмисно вимикає інсталяцію). md::KenshiLandFile(name, fallback) повертає <KENSHI_DIR>/data/newland/land/<name>, якщо файл є, інакше запасний шлях, і пише вибір у лог один раз. Тести зі справжніми даними запускаються лише з KENSHI_DIR.

ModsМоди

Mods are read the way Kenshi reads them: data/mods.cfg order, then the mods/ and Steam Workshop folders; records are merged in load order (io/fcs_gamedata.h). Edit content in Kenshi's FCS. Workshop mods are not yet verified on real data.

Моди читаються так, як їх читає Kenshi: порядок з data/mods.cfg, далі теки mods/ і Steam Workshop; записи зливаються в порядку завантаження (io/fcs_gamedata.h). Контент редагується у FCS. Моди Workshop на справжніх даних ще не перевірені.

Data flow at startupПотік даних під час запуску

Kenshi install (read-only, KENSHI_DIR)
 ├─ data/gamedata.base, *.mod, mods.cfg ─► io/fcs, io/fcs_gamedata ─► world/BiomeRegistry (merged with mods)
 ├─ data/newland/land/fullmap.tif ───────► io/tiff ─► world/TerrainAtlas (3.6 m) + TerrainLodTree (1.8 m window)
 └─ data/newland/land/*.png, textures ───► io/kenshi_dir (lookup by file name) ─► terrain maps and layers
                                                │
     render: terrain LOD ─► 8-byte G-buffer ─► ground resolve (Kenshi's ground shader) ─► SDL_GPU / Vulkan

Still offline copies in the private repository (fallbacks only): baked ground/detail textures and converted character meshes. They are being replaced by reading the install at runtime.

Поки ще офлайн-копії в приватному репозиторії (лише запасні): випечені текстури ґрунту й деталей, сконвертовані меші персонажів. Їх замінює читання інсталяції під час запуску.

TerrainЛандшафт

  • Heights: TerrainAtlas keeps every 2nd sample of fullmap.tif (3.6 m) for the whole world; TerrainLodTree reads a 1.8 m window (Kenshi's grid) around the camera on a background thread.
  • Queries: TerrainQuery is the single source of heights, normals and slopes for gameplay.
  • Geometry (LOD, default): quadtree with Kenshi's screen-space error rule (viewport height × node error / distance, 5 px near, 35 px far, ramp 750 → 1500 m), geomorph, skirts, per-vertex normals from six neighbours; patch 16 ("Small") or 64 ("Large").
  • Shading: 8-byte G-buffer (position fractions + octahedral normal), then a screen-space resolve running Kenshi's ground shader: per-pixel biomes from blendMap (four channels plus the cell's fifth slot), per-pixel cliff weight, one mip down for landscape layers (Kenshi's default texture quality); flat layers are skipped where the cliff fully covers them.
  • Scatter: FeatureScatterSystem places objects from Kenshi's features.dat.
  • Висоти: TerrainAtlas тримає кожен 2-й відлік fullmap.tif (3,6 м) для всього світу; TerrainLodTree читає вікно 1,8 м (сітка Kenshi) навколо камери у фоновому потоці.
  • Запити: TerrainQuery — єдине джерело висот, нормалей і схилів для ігрової логіки.
  • Геометрія (LOD, за замовчуванням): квадродерево за правилом екранної похибки Kenshi (висота вікна × похибка вузла / відстань, 5 px поблизу, 35 px вдалині, перехід 750 → 1500 м), геоморф, спідниці, нормалі у вершинах з шести сусідів; патч 16 («Small») або 64 («Large»).
  • Шейдинг: 8-байтовий G-буфер (дробові частини позиції + октаедрична нормаль), далі екранний resolve із шейдером ґрунту Kenshi: біоми для кожного пікселя за blendMap (чотири канали + п'ятий слот клітинки), вага кручі для кожного пікселя, шари ландшафту на один mip нижче (якість текстур Kenshi за замовчуванням); плоскі шари пропускаються там, де їх повністю закриває круча.
  • Об'єкти: FeatureScatterSystem розставляє об'єкти з features.dat Kenshi.

Performance measurementЗаміри продуктивності

  • Only on terrain-dominated frames: scenarios place the camera with set_camera_pose_world and check md.terrain_pixel_fraction() ≥ 80 %.
  • RenderPassGraph switches any registered pass on or off at runtime (md.set_render_pass_enabled); with md.get_gpu_ms() this splits frame cost pass by pass without rebuilding.
  • A/B comparisons run in one process, several interleaved blocks (ABBA), to cancel GPU clock drift.
  • Fixed flight route, 1920×1080, HD 520: p99 30–31 ms (13.10.2026) → ≈ 19 ms (17.10.2026) → ≈ 15.0 ms (19.10.2026). Ground texturing (the resolve) is still the largest part of the frame.
  • Ground shimmer is measured numerically, not by eye: reprojection residual of the ground between consecutive frames while the camera moves.
  • Лише на кадрах, де переважає земля: сценарії ставлять камеру через set_camera_pose_world і перевіряють md.terrain_pixel_fraction() ≥ 80 %.
  • RenderPassGraph вмикає й вимикає будь-який зареєстрований прохід під час роботи (md.set_render_pass_enabled); разом з md.get_gpu_ms() це розкладає ціну кадру по проходах без перезбірки.
  • Порівняння A/B — в одному процесі, кількома чергованими блоками (ABBA), щоб прибрати дрейф частот GPU.
  • Фіксований маршрут польоту, 1920×1080, HD 520: p99 30–31 мс (13.10.2026) → ≈ 19 мс (17.10.2026) → ≈ 15,0 мс (19.10.2026). Текстурування ґрунту (resolve) — досі найбільша частина кадру.
  • Мерехтіння ґрунту міряється числом, а не на око: залишок репроєкції ґрунту між сусідніми кадрами під час руху камери.

Editor & toolsРедактор та інструменти

The tools repository (GPL-3.0) holds the standalone monkey_dust_editor (Dear ImGui): a Kenshi-style character editor (body sliders scale bones, as Kenshi does), a Settings tab (upscaling mode, resolution_scale, terrain chunk size), a 3D world view and inspectors. It also holds shader hot-reload, the live game command driver used for all measurements, offline converters, and two small local MCP servers for development (read-only Ghidra project access, headless RenderDoc capture reading; no network code).

Репозиторій інструментів (GPL-3.0) містить окремий monkey_dust_editor (Dear ImGui): редактор персонажів у стилі Kenshi (слайдери тіла масштабують кістки, як у Kenshi), вкладку Settings (режим масштабування, resolution_scale, розмір патча ландшафту), 3D-перегляд світу й інспектори. RulesПравила

Kenshi data and third-party code

  • No Kenshi files in public repositories or releases.
  • Kenshi's own code (shaders, executable) is never copied. Behaviour is ported from permissively licensed open-source code (attributed in THIRD_PARTY.md) or re-implemented from facts; parity is checked against Kenshi's own code, not only against screenshots.
  • Every claim about Kenshi is backed by its code or data (address, file and line, or a number), not by screenshots.

Code

  • C++17 only.
  • No heap allocation and no std::vector/std::map growth on hot paths; fixed arrays.
  • No assert(): MD_LOG_WARNING(...) and return. No registry mutation inside iteration: collect → apply.
  • The engine never includes from game/ or tools/. ImGui only under MONKEY_DUST_EDITOR.

Дані Kenshi і сторонній код

  • Жодних файлів Kenshi в публічних репозиторіях і релізах.
  • Власний код Kenshi (шейдери, виконуваний файл) не копіюється. Поведінка переноситься з відкритого коду з дозвільною ліцензією (атрибуція в THIRD_PARTY.md) або відтворюється за фактами; паритет перевіряється за кодом самої Kenshi, а не лише за скриншотами.
  • Кожне твердження про Kenshi підтверджується її кодом або даними (адреса, файл і рядок, число), а не скриншотами.

Код

  • Лише C++17.
  • На гарячих шляхах — без виділень пам'яті й росту std::vector/std::map; фіксовані масиви.
  • Без assert(): MD_LOG_WARNING(...) і return. Без змін реєстру під час обходу: зібрати → застосувати.
  • Рушій не включає файли з game/ чи tools/. ImGui — лише під MONKEY_DUST_EDITOR.
